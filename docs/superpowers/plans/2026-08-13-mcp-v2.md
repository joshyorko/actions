# MCP v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move Action Server to the MCP 2026-07-28 stateless SDK v2 `/mcp` contract while preserving Action tool, resource, template, prompt, auth, request-context, and MCP Apps behavior.

**Architecture:** Use the public low-level SDK v2 `Server` constructor handlers and `Server.streamable_http_app(stateless_http=True)` as the sole mounted route. Keep catalog registration in the existing Action Server lifecycle, adapt each handler to v2 result models and request context, and retain API-key authentication at the `/mcp` boundary.

**Tech Stack:** Python 3.12, FastAPI/Starlette, MCP Python SDK 2.0.0, pytest, local monorepo source resolution.

## Global Constraints

- `/mcp` is the sole modern stateless endpoint; remove SSE and legacy transport/session plumbing.
- Do not add initialization/initialized compatibility, session IDs, sticky routing, or transport state.
- Use only public MCP SDK v2 APIs and snake-case Python model fields.
- Preserve schemas, annotations, structured/unstructured results, headers/cookies/secrets, API-key auth, reload, and MCP Apps `_meta`.
- Do not publish, push, open PRs, mutate GitHub, change secrets/config, or regenerate deferred publication locks.
- Improve the canonical repository guide with verified MCP v2 source/test evidence in the implementation commit.
