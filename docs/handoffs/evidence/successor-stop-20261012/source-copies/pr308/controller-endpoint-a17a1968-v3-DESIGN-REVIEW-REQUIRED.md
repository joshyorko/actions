## Concrete proposed process/ownership shape

Use one existing Linux subreaper for exactly two serial native test nodes. The outer launcher process becomes the independent endpoint guardian of that original Popen. It performs only bounded nonblocking control-channel observation, Popen poll/reap and birth-verified escalation after launch. The subprocess executes the tests, reader/sampler stop, owned census, full-output hashing/fsync and final receipt persistence. A blocking operation in that subprocess is therefore inside the guardian's endpoint; no Python thread inside it is called an independent watchdog. No additional subreaper, standalone process killer, infrastructure or cgroup mutation is introduced.

The guardian's owned namespace/fds and source/profile/RCC/toolkit admission are validated before the launch origin; preparation has its own bounded preflight and does not perform RCC acquisition. The one monotonic origin T0 and all absolute endpoints are then transmitted explicitly. The guardian retains the original Popen object as the sole direct-child waiter; adopted waitpid drainage remains the existing subreaper's responsibility. Before descendants become guardian signal authority, capture root and descendant PID/birth pairs bracketed by original Popen liveness and stable root birth. Revalidate births before each signal. Unknown/reused/disappeared observations cannot grant new authority. Never call legacy _fallback_reap_after_error or grace-reset terminate_process_tree on this native path. Kernel scheduling/blocked I/O limitations must be stated; watchdog intervention does not prove reaping.

The outer process must not synchronously read/hash/fsync output or final receipt after T0: such work belongs to its subprocess. Guardian failure reporting uses fixed outcome classes, existing pre-opened bounded control fds and exit status; no potentially blocking receipt-repair operation is inserted after the hard endpoint. Full receipt readback/independent verification occurs after execution and is a separately bounded read-only gate. The execution interval includes receipt persistence, while post-execution verification is explicitly separate. Review must accept this scope before any whole-endpoint claim.

## Budget and outcome contracts

A typed NativeEndpointPlan carries T0, work_deadline, cleanup_deadline, evidence_deadline, term_deadline and hard_deadline. Strict finite/order validation rejects unset, bool, NaN, reversed, reused-origin and unaccepted profiles. Tiny injected plans are source controls only. For native, 630 TERM /640 KILL are proposals inherited from design review; no internal work/cleanup/evidence allotment or memory number is admitted yet. All waits, sleeps and joins use the same remaining absolute budget with zero when exhausted; no new grace after any primary/secondary failure. Root must review exact plan and admission evidence before a process can be created.

The guardian first requests termination at its admitted term endpoint; at hard endpoint it can only escalate identities already proved owned and reap its original wrapper with remaining budget. Missing confirmation is explicit unavailable/incomplete. Any intervention, failed census, surviving reader/sampler, missing lease release, unexpected descendant, receipt/hash failure or incomplete output is FAIL even if pytest returned0. Unknown identities are never normalized to absent; absence is not an observed reap event. Preserve original primary exception identity/cause and fixed secondary classes. A successful receipt is accepted only if the subreaper finished and persisted all measured facts before endpoint and the independent guardian exited without intervention.

## Native-only disk-output contract

Introduce a separate NativeExecutionOutcome rather than replacing legacy CompletedProcess stdout/stderr strings with paths. Open task-owned stdout/stderr files using directory-fd-relative O_CREAT|O_EXCL|O_NOFOLLOW, checking regular file type, nlink, current uid/gid, exact approved modes and pinned parent dev/inode. Ownership policy remains0700 home /0750 approved directory scope, with no broad mode relaxation. Pass opened file descriptors into the existing subreaper/command; retain raw bytes on disk, not full decoded strings or JSON copies. The subprocess computes stream size/SHA256 in bounded chunks, checks fd identity before/after and fsyncs within evidence_deadline. Write full untruncated identity/census and output descriptors to an exclusive final receipt file under the same pinned namespace. Non-following temp/final writes and directory fsync must remain inside the guarded subprocess.

A small fixed control frame reports terminal outcome and descriptor identities without serializing uncapped census or stdout/stderr. Full census lives in the receipt, not a truncated frame. The guardian must reject malformed/duplicate/incomplete control frames and a success frame before receipt persistence. Missing/partial output is preserved with explicit unavailable/hash-incomplete classes. No failure path fabricates checksums or cleanup success. An interrupted writer cannot replace a PASS receipt with a patched summary.
