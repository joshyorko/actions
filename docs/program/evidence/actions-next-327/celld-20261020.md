coordinator from this checkpoint. This is a blocker for the optional celld
increment only; it does not change the existing queue backend or its authority.

## Evidence and blocker

At the Actions checkpoint, `SQLiteAdapter.reserve_fenced` claims under
`BEGIN IMMEDIATE`, advances the claim epoch, and uses SQLite time. Fenced
completion rechecks owner, epoch and expiry in the same transaction that writes
parent-linked outputs. This remains the sole Work Item authority in this lane.

celld v0.6.2 requires conditional create and compare-and-swap, read-after-write
consistency and ranged reads from its fleet bucket. Its default fleet durability
requires two running nodes. Its `diagnose` command checks the storage contract.
The upstream guide explicitly says community MinIO is not production-qualified;
`celld dev` uses a local SQLite object store and is not a substitute for fleet
storage or two-node recovery. The beta security guide also requires a trusted
private network for peer traffic and a separate credential boundary per fleet.

No supported bucket endpoint was selected or supplied for this synthetic lab.
The pinned x86-64 celld release archive was fetched and matched GitHub's
published SHA-256 (`ce0ee3552cc8d55dde3998dc3b1b0c8f547bbcb4bc803d2a94842368b047646c`);
the executable reports `celld 0.6.2`. The official celld GHCR image and MinIO
images from Docker Hub and Quay were denied by their registries. The official
MinIO archive and checksum URLs for `RELEASE.2025-09-07T16-13-09Z` returned HTTP
410. No matching containers were cached. No credentials were inspected and no
fleet was started. Without an authorized bucket/runtime path, the storage
diagnostic and fault lab remain unrun. The available host RCC is `v18.19.7`;
this repository pins `v18.19.3`, so the documented RCC toolkit gate was not run.
