# Portable post2 compiler preparation

SOURCE PREPARATION ONLY. No compiler environment has been built by this adapter. It derives from the committed a44 managed compiler recipe, updates exact post2 Runtime/source pins, retains Core a6 and Work Items a2, and requires a fresh target-selected absolute root. It uses normal public dependency resolution; there is no imported catalog, fixed /tmp pathname, producer trust, credential, key, receipt or cache reuse.

Deliver this directory beside the already verified post2 candidate. `public-input-manifest.json` independently records exact source, wheel, RCC and package hashes. Candidate layout must contain `consumer/bin/python`, `source-sha.txt` and `wheels/` with the three exact wheels. Candidate source is `46488e59f419d6bb55ab594031a0f227b4e0d817`; Runtime is `1.1.0a44.post2`. The adapter verifies installed distribution versions and every wheel payload member before compilation. The standalone `package.yaml` bytes must match the script's embedded fixture, SHA256 `f7b4173c11a7eef06cf2ecc526d15a7f069efdd4d465f65cb0fb6258d258b4a8`.

Prerequisites: Linux x86_64, existing post2 CPython 3.12 consumer Python launched with `-I` and without `-O`, bundled executable RCC 18.19.3 with the manifest SHA256, installed psutil, readable exact wheels, normal configured public Conda/PyPI connectivity and existing TLS trust. No download of RCC is needed. Root parent must exist with canonical non-symlink ancestry; compiler root must not exist. Admission requires 4.25 GiB free; compiler lane cap is 2 GiB with 1 GiB consumer floor. These are the previously reviewed managed-consumer limits, not the producer's separate 10 GiB reserve. Public dependency resolution may fail due network restrictions; preserve that failure and do not change proxy, security or trust settings to bypass it.

Choose your own absolute paths (substitute each placeholder):

```text
CANDIDATE/consumer/bin/python -I ADAPTER/prepare-compiler-managed.py --candidate-base CANDIDATE --compiler-root FRESH_TARGET_ROOT
```

Run in a fresh dedicated process, not a process already owning unrelated children. The adapter is a bounded subreaper: version 30 seconds, publish 600 seconds, proof 180 seconds, combined logs 12 MiB; it kills/reaps owned descendants on exit and retains capacity/cleanup outcomes. Run only after other heavy work has stopped. Do not run concurrently with the release suite.

The real HOME value is passed unchanged. ROBOCORP_HOME, ACTIONS_HOME, TMPDIR and PIP_FIND_LINKS point beneath the fresh root. Only existing unauthenticated proxy values and TLS certificate configuration are preserved; credentials are not copied. Unlike the earlier recipe, there is no private HOME reassignment. RCC's explicit ROBOCORP_HOME controls its cache/trust/artifact roots, and pip receives only the exact Core wheel through local find-links. We have NOT dynamically proven that all third-party tools avoid incidental writes beneath real HOME; this recipe therefore makes no universal HOME-write-containment claim. No real-HOME content is copied or deleted. If strict zero-write HOME containment is required, stop for a supported reviewed environment route rather than remapping HOME or changing permissions.

Successful publish generates target-local trust and observed specification/artifact digests. Proof runs via installed `build_exec_command`, `--no-build`, and Python `-I`; `verify-core.py` checks all 87 Core payload members (82 Python), retired dependency absence, target-local interpreter origin and isolated Data scan context. Only then does `target-config-fragment.json` provide the newly measured prepared receipt, trust root, digests and proof hash for the managed UI adapter. Never replace those values with producer evidence. This does not start an auth server, grant access, configure browser/UI, or establish UI acceptance.

## Cancellation correction

The initial recipe was held in review because default SIGTERM could bypass cleanup. The corrected standalone process installs SIGTERM/SIGINT handlers, remembers the first stop request, routes it through existing bounded cleanup, defers repeated signals during cleanup and refuses to start another phase after any stop. Prior handlers are restored after cleanup. `cancellation_probe.py` extracts the actual nested run function without invoking main: a synthetic Python child receives the lifecycle, SIGTERM triggers cleanup, additional SIGTERM/SIGINT arrive during group termination, the child is reaped, and a subsequent phase is rejected. No RCC or network process is launched by this probe. `review-hold-signal.md` preserves the original HOLD; this is a local adapter defect, not an upstream issue.
