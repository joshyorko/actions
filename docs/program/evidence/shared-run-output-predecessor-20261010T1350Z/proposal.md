## One Run lifecycle, normalized extensions

Keep existing Run.id, Run.status and Run.result authoritative. Add RunPin keyed by Run.id with Workspace, immutable DeploymentRevision/PackageRevision/Capability/RuntimePlan/worker/policy/binding references, admission actor/decision receipt, current_attempt_id, monotonic epoch and durable cancel_requested flag. This is a normalized extension joined to Run, not a second Run table or shadow status/result ledger.

Add RunAttempt (generated ID, Run FK, monotonic attempt number, owner ID, epoch, DB lease deadline and heartbeat, attempt outcome), and RunOutput (generated ID, Run and Attempt FKs, epoch, Workspace/Deployment scope, provider profile revision and opaque object reference, digest/size/name/media/purpose/schema, provisional/final/aborted/expired state and retention deadline). Provider object names are never the public output identity. Output is attached by an explicit output-ID list in the existing Run.result envelope; no independent authoritative result field is added.

Legacy Runs have no RunPin and retain existing behavior. All common Run mutations must use a shared transaction helper: legacy _update_run can update only a Run with no RunPin; scoped Run transitions require the matching current Attempt/owner/epoch and lease predicate. This prevents the old unconditional helper from defeating the new fence. DB changes happen before in-memory Run/cache changes, and caches are notifications, never authority. Terminal status/result and output FINAL transitions are a single commit. Direct SQL by trusted DB administrators is outside worker authority; public Runtime workers do not receive raw Database mutation access.

## Minimum shared interfaces

- admit_run(authenticated_actor, deployment_revision_ref, capability_ref, normalized_inputs, idempotency_key): resolve an existing control-plane-admitted immutable snapshot, check current Workspace/Deployment execute grant, insert the existing Run plus RunPin atomically. An arbitrary supplied digest/ref cannot create the admitted registry row.
- claim_attempt(run_id, owner_id, lease_duration): conditional pending/retryable Run claim, current pointer/epoch increment and Attempt insert atomically. Reclaim only after a DB-time expired lease; retry retains RunPin references. No adapter selection or automatic external-side-effect retry is introduced.
- heartbeat(attempt_fence, lease_duration): conditional current owner/epoch/unexpired lease update. An expired fence cannot renew itself.
- stage_output(attempt_fence, metadata, bounded_input_stream): authorize configured provider from pinned admission, create PROVISIONAL metadata conditionally, write generated provider object through bounded incremental hashing and close/seal. Provider-issued seal receipt binds object reference/digest/actual byte count; caller-declared fields alone are not proof.
- publish_success(attempt_fence, sealed_output_ids, typed_result): in one transaction recheck grant/admission policy as required, current fence and lease/cancel/nonterminal predicate, verify staged receipts and ownership, update Run.status/result and outputs to FINAL. Return the existing Run result with RunOutputRef values. No independent finalize-then-attach window in this first slice.
- request_cancel(authenticated_actor, run_id): serialize on the same Run row and persist intent. If cancel wins before publish, publish rejects; if publish commits first, cancellation reports terminal without pretending to undo side effects.
- resolve_output(authenticated_actor, RunOutputRef): authorize current persisted Workspace/Deployment read grant, load the authoritative joined RunPin/Run/FINAL output attachment, enforce retention, then obtain a provider-bound reader. No output metadata/provider existence lookup is exposed to an unauthorized actor. Return public metadata plus a context-managed bounded reader, not a Path or a signed/provider URL.

RunOutputRef is a strict versioned object {workspace_id, run_id, output_id}; IDs are generated canonical UUIDs. The Workspace component is an expected-scope discriminator, never a grant. A replayed ref is reauthorized against current policy. Internal AuthenticatedActor is produced only by a trusted transport/control-plane authenticator; accepting an actor ID from package arguments or request JSON is prohibited. The private service cannot claim public authentication wiring until a real adapter supplies this context.

## Concrete authority prerequisite

The service needs actual persisted control-plane records: Workspace, admitted DeploymentRevision snapshot and explicit actor grants scoped to Workspace/Deployment and operation. Initial grants are exact allow records with default deny, revoked/disabled deny, no wildcard inherited app grant. Their administration is a trusted control-plane operation, unavailable to action/package code. Provider profiles are separately admitted server configuration; a package cannot nominate a filesystem root/credential/object key.

The admitted snapshot store can initially contain a narrowly registered trusted test/admin snapshot; registration must be marked control-plane-only and must not claim #135 compiled package authenticity. The first proof exercises real grants and durable pins, not a bool callback or fabricated "verified" field. A production default Workspace must eventually be persisted once, not derived from port/path/PID. Public transport must map a verified principal to actual grants; current global-token SimpleUser is not silently upgraded into a multi-Workspace policy.

## Transactions, time and concurrency

Use only existing Database/connection/transaction/adaptation. Acquire a real DB row write lock on the Workspace authority row, then Run row, then Attempt/output rows in a fixed order; SQLite acquires its interprocess writer lock through the first authority UPDATE, PostgreSQL serializes the same row UPDATE. Do not rely on Database._write_lock as an interprocess lock. Grant revocation and admission/finalize use the same Workspace lock, so policy checks do not race a committed revocation.

Compare lease deadlines using database time at the conditional statement, not worker time. PostgreSQL clock_timestamp() is required rather than transaction-start now(); SQLite statement-time julianday('now') conversion can provide integer milliseconds. Keep backend SQL in a small Database-supported helper or this private service through the existing facade; do not introduce another backend or raw psycopg connection. A conditional UPDATE ... RETURNING Run.id with exact owner/epoch/current pointer/nonterminal/no-cancel/unexpired lease yields one winner. All later output/result changes are in its transaction and any failed predicate/commit rolls back the whole metadata change. Provider I/O happens outside the short transaction; sealed orphan objects are nonauthoritative after rollback and can later be aborted/collected. Full GC/retention workers and side-effect ambiguity policy are deferred.

Successful identical finalize replay returns the already stored same result only after reauthorization and exact immutable result/output equality; a different result/output list fails. Old owner replay cannot overwrite the terminal record. Two independent processes claiming/finalizing/reclaiming must be tested on SQLite and available PostgreSQL. DB backend/type/migration errors fail closed; no missing-table fallback and no PostgreSQL-to-SQLite fallback.

## Provider/read boundary

Use a private output-provider protocol with a concrete filesystem-backed implementation configured by trusted control plane. Local and shared-mounted roots use the same opaque generated object IDs; independently constructed service instances can read the same object/metadata. Pin/open/read owned descriptors with no-follow regular-file checks and generated flat names, bound bytes and verified seal metadata, close on every path. Do not return the pathname to FileResponse. Content-addressed dedup does not merge grants. This initial provider proof can be explicitly Linux-only and context-managed reads; Windows reparse/HTTP Range/HEAD/static-serving parity and an object-store provider remain #86 gates, not implied acceptance.

Storage is trusted service-owned output storage, not a hostile complete-tree snapshot. Secret output redaction/policy enforcement must occur before stage/final publish; the service cannot infer whether arbitrary bytes contain credentials. Output policy/receipt fields must be explicit. Bounded stream/size/result limits are chosen for this private slice and documented, not presented as the full large-result provider contract.
